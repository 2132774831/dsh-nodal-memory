# 独立版记忆软件（不依赖 DeepSeek Harness）

## 怎么启动

双击 **`启动记忆软件.cmd`**。

它会自动找 node、起本地服务、打开浏览器。窗口关掉服务就停。

命令行方式（想改参数时用）：

```powershell
node app\server.mjs
node app\server.mjs --port 8080            # 换端口（默认 7787，被占用会自动往后试）
node app\server.mjs --data D:\mymem        # 换数据目录
node app\server.mjs --seed D:\old.json     # 首次启动导入一份 v1 JSON 库
node app\server.mjs --open                 # 起完自动开浏览器
```

## 出了问题怎么查

| 现象 | 原因 / 处理 |
|---|---|
| **双击后窗口一闪而过** | 先确认 `启动记忆软件.cmd` **还是原来的字节**。这个文件必须是**纯 ASCII + CRLF 行尾**——用编辑器（VSCode 等）保存成 UTF-8 或 LF 行尾，cmd.exe 会把脚本拆碎执行，表现就是闪退。`node --test test/app.test.mjs` 里有一条测试专门守这个 |
| 窗口留着但浏览器没开 | 手动打开命令行里打印的地址（默认 `http://127.0.0.1:7787`） |
| 端口被占用 | 会自动往后试端口，看打印出来的地址 |
| `[ERROR] Node.js not found` | 装 Node.js 18+，或把 node 加到 PATH |
| 页面打开是空的 | 看命令行窗口有没有报错；数据目录里是否有 `dsh-local-memory.db` |

出问题时在命令行里手动跑，能看到完整报错：

```powershell
node app\server.mjs --port 7787
```

## 数据在哪

默认在 **`app\data\`**，就一个 SQLite 文件：

```
app\data\dsh-local-memory.db      记忆库（主）
app\data\dsh-local-memory.db-wal  SQLite 的预写日志
app\data\dsh-local-memory.v2-config.json  配置
```

**它不会读写 `~/.dsh` 里的真实记忆库。** 启动时程序会把 `DSH_HOME` 指到上面这个目录，
所有路径都从那里派生——这也是为什么它可以和 DSH 插件并存而不打架。

想备份：把整个 `data` 目录复制走就行。想重来：删掉 `data` 目录。

## 首次启动会自动导入旧记忆

`启动记忆软件.cmd` 默认会带 `--seed "%USERPROFILE%\.dsh\dsh-local-memory.json"`：

- 只在 `data\` 里还没有库时导入
- **只复制，不改源文件**
- 导入后自动迁移成 SQLite（v1 的 JSON 格式）

所以第一次打开就能看到你现有的记忆，而不是空库。

## 三个页签

| 页签 | 干什么 |
|---|---|
| **关系图** | 两种视图，点「视图」按钮切换：<br>· **圆点图**：点＝记忆（颜色按类别、大小按连接数），看整体结构最快<br>· **工作流**：卡片式节点，标题栏按类别着色，卡内是项目/类别/时间/连接，贝塞尔连线<br>**左键**点节点→右侧看详情；**右键**点节点→弹窗看全文（可复制）。红圈虚线＝孤岛。「孤岛视图」只留孤岛。**「语义」开关**控制要不要按 embedding 相似度连边。视图模式会写进地址栏（`#graph/cards`），刷新后保持 |
| **记忆列表** | 搜索（中文两字词也命中）、新增、编辑、删除（软删可恢复）、彻底删除、看已删 |
| **补标** | 逐条给未分类记忆归类（工作/偏好/情感），顺手改重要度和标签 |
| **直觉** | 两块：**该想起的**（重要、搁了很久、几乎没用过的那几条）+ **疑似冲突**（说同一件事但关键处不一样的两条）。只列候选，不改任何数据 |
| **设置** | 概况、**功能开关**、**语义检索（embedding）**、**维护**、**数据**（库与配置路径/导出 Markdown） |

### 功能开关（全部可以关，关了不删数据）

| 开关 | 默认 | 关了会失去什么 |
|---|---|---|
| 语义连线 | 开 | 图上没有紫色点线（其余四类边还在） |
| 疑似冲突标黄 | 开 | 图上不再标黄圈 |
| 疑似冲突扫描 | 开 | 直觉页不出「疑似冲突」 |
| 该想起的 | 开 | 直觉页不出「该想起的」 |
| 同项目边 | **关** | 少一类很弱的边（59 条同项目曾连出 1711 条边，那是毛线球的主要来源） |
| 时间相邻边 | 开 | 布局会塌成一团——它本身没信息量，但它是唯一把记忆按时间串开的力。这是实测出来的，不是猜的 |

**冲突灵敏度**三档，实测在真实 75 条数据上的差异：

| 档位 | 判据 | 挑出 |
|---|---|---|
| 严格 | 正文余弦 ≥0.26 / 向量 ≥0.78 | 0 对 |
| 标准（默认） | ≥0.20 / ≥0.72 | 3 对 |
| 宽松 | ≥0.14 / ≥0.64 | 20 对 |

嫌「只有几个黄点」就调宽松；嫌吵就调严格。

### 关系图的操作

| 操作 | 效果 |
|---|---|
| 左键点节点 | 右侧栏显示详情；**同时浮出"最像它的几条"**（紫色点线 + 紫圈，只画还没连线的） |
| 右键点节点 | 弹窗显示全文 + 复制按钮（Esc 或点别处关闭） |
| **鼠标悬停在卡片上** | **只亮它和它的邻居，其余压暗**；连线用对端记忆的身份色，一眼看得出线通向谁 |
| 拖节点 | 手动摆位置（会带动邻居重新找位置） |
| 拖空白处 | 平移 |
| 滚轮 | 缩放 |
| 「适应窗口」 | 重新居中 |
| 「重新布局」 | 抖散重排 |
| 「视图」 | 圆点图 ⇄ 工作流卡片图 |

### 工作流视图的配色规则（重要）

| 位置 | 表示什么 | 为什么这么设计 |
|---|---|---|
| 卡片**标题栏**颜色 | **类别**（工作/偏好/情感/未分类） | 回答"这是什么" |
| 卡片**左侧竖色条** | **这条记忆自己的身份色**（由 id 哈希，永不变化） | 回答"这是哪一条" |
| 连线**颜色**（平时） | 关系类型，统一压暗 | 75 个点 284 条边，如果给每条线都上不同的色，会变成彩虹面条反而更看不清 |
| 连线**颜色**（悬停时） | 对端记忆的身份色 | 回答"这根线通向谁" |
| 连线**粗细/虚线** | 共现最粗 → 共享标签 → 语义相近（紫点线）→ 同项目 → 时间相邻虚线 | 关系的强弱 |

一句话：**平时看结构（柔和的网），指着某张卡看它的关系（只有那一簇亮着）。**

**联想**只在"点一下"（选中）时出现，悬停不画——悬停是扫关系，点一下才是"我想看看这条和什么有关"。
紫色点线指向的是"最像它、但还没有正式连线"的记忆（相似度 ≥0.50，每点最多 5 条）。
真实 75 条数据上有 **99 条这样的暗线，覆盖 41 条记忆**——都是标签和共现没能连上的关联。

### 五种连线的含义

| 关系 | 怎么来的 | 可信度 |
|---|---|---|
| **共现** | 两条记忆在同一次检索/注入里同时被命中 | 最强——是使用痕迹，不是猜测 |
| **共享标签** | 标签交集，按 idf 加权 | 强——同一条人工标签 |
| **语义相近** | 向量余弦相似度 ≥ 阈值（默认 0.60），每点最多留 3 条 | 中——模型判断，可能有偏差；可在设置里关掉 |
| **同项目** | 同一个 project 字段 | 弱——只说明"同一摊事" |
| **时间相邻** | 创建时间接近 | 最弱——纯布局用 |

语义阈值的默认值 0.60 是**量出来的**：真实 75 条记忆两两相似度 min 0.13 / p50 0.34 /
p90 0.46 / p99 0.60 / max 0.82。用常见的 0.8 会只连出 0~2 条，等于没有。
0.60 能连出 14 条，且其中一半与已有关系重合（互相印证）。

### 「直觉」页的两套判据（都是量出来的，不是拍的）

**该想起的**：`重要度 × log(搁了几天) ÷ log(1+用过几次)`，只取搁了 ≥14 天、用过 <5 次的。
逻辑是"正被遗忘、但值得记住"——最新的和常用的都已经在列表和搜索里了，不需要再占一个位置。

**疑似冲突**：要同时满足两条，缺一不可。
1. **说的是同一件事**：正文 token 余弦 ≥ 0.20，或向量相似度 ≥ 0.72；
2. **有矛盾痕迹**：出现了互斥表述（需要/不需要、成功/失败、启用/禁用…）或**关键值不同**（版本号、路径、端口）。

两个踩过的坑，都留在注释里了：
- **正文相似度不能用 Jaccard**。这批记忆每条几百字，Jaccard 被长度摊薄，全库最大才 0.168，
  用 0.28 当阈值等于永远不命中。token 余弦对长度不敏感，同一件事能到 0.20~0.29。
- **互斥词不能用单字或高频词**。拿"是/不是"去判，中文里"是"满地都是，几乎每对都命中，
  一跑就挑出 50 对噪声。只保留语义明确、出现频率低的成对词。

在真实 75 条数据上，这套判据挑出 **3 对**候选，都在"值得扫一眼"的范围内。

## 已验证到什么程度

- 服务器与接口：**13 项测试**（真起 HTTP 服务真打接口），含路径穿越防护、种子导入不改源文件
- 布局算法：与插件共用 `src/core/graph-layout.js`，20 项相关测试
- 界面：三页签已在无头浏览器里截图核对（真数据 75 条迁入、68 条未分类）
- **没验证的**：真人鼠标交互（拖拽/缩放/点击）只按 API 写对了，我没有手

第一次上手建议按这个顺序点一遍：

1. 关系图页：拖一个节点 → 滚轮缩放 → 点一个节点看右侧详情
2. 点「孤岛视图：开」→ 应该只剩那 11 个红圈点
3. 列表页：搜「插件」→ 应命中多条；新增一条再删掉
4. 补标页：给一条点「工作」→ 它应该从队列消失，顶部数字减一

## 和 DSH 插件的关系

两者共用同一个内核 `src/core/`（零宿主依赖）：

```
src/core/        ←  内核（存储/检索/时间/图/维护/embedding）
   ├── app/         独立软件：本地 HTTP 服务 + 浏览器界面
   └── src/host/    DSH 插件：注册工具、注入提示词（同一套 API）
```

插件那边**没有切换**（`main` 仍指向 v1 的 `lib/`），所以两边可以并存：
独立软件用 `app/data`，插件用 `~/.dsh`，互不干扰。

## 已知限制

1. **只有本机能访问**：绑定 `127.0.0.1`，没有账号体系。别用 `--host 0.0.0.0` 暴露到局域网。
2. **界面没有前端框架**：原生 DOM，改起来直接但要自己管状态；没有虚拟滚动，几千条记忆时列表会慢。
3. **关系图 O(n²) 斥力**：几百个点很流畅，上千个会掉帧（需要四叉树优化）。
4. **embedding 需要外部端点**：默认关闭；配了之后存记忆时会同步算向量（会慢一点）。
5. **没有导入 Markdown**：目前只支持从 v1 JSON 导入。
